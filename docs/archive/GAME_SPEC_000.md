# Clap-Clap 拍手对战 · 五行玩法实现说明（当前已实现）
如果有编号更新的SPEC文档，请去阅读新的SPEC文档。
> 单机人机对战：玩家（P1）vs AI（P2）。纯 HTML + CSS + JS，无构建步骤，直接用浏览器打开 `index.html` 即可游玩。

## 1. 核心循环
**准备（选择动作）→ 同步结算 → 展示战报 → 下一回合**，直至一方 HP 归零。

## 2. 资源系统（五行元素）
- 元素共五种：**金（Jin）、木（Mu）、水（Shui）、火（Huo）、土（Tu）**。
- 每元素初始 **0**，上限 **9**（`MAX_ELEMENT`）。
- **可接取**：金、木、火（`GATHERABLE_ELEMENTS`）。接取一回合 +1。
- **暂未开放**：水、土。接取会被引擎强制改为防御，UI 中置灰并提示"暂未开放"。

## 3. 动作系统
每回合三选一（接取 / 使用 / 防御），动作内部表示为 `{ type, element, route, amount }`：

| 动作 | type | 说明 |
|---|---|---|
| 接取 | `gather` | 选择金/木/火之一，+1 |
| 使用 | `use` | 选择元素 → 路线（见 §5），按路线消耗资源 |
| 防御 | `defend` | 本回合受到的每个伤害事件 **-1**（最低 0），并**驱散灼烧/寄生状态** |

- 输入兼容：`normalizeAction` 会把缺失字段归一化；`formatAction` 输出中文战报文案。
- 路线在 `ROUTES` 中定义，成本分三类：固定数值（`cost: N`）、全部（`cost: 'all'`）、加特林按量（`cost: 'amount'`）、穿甲弹（`cost: 'ap'`）。

## 4. 判定表（双方行动同时生效）
| 双方动作 | 结算结果 |
|---|---|
| 使用 vs 使用 | 双方各按其路线结算，伤害同时生效 |
| 使用 vs 接取 | 接取方照常 +1 元素，正常吃伤害 |
| 使用 vs 防御 | 防御方每个伤害事件 -1（最低 0），并驱散灼烧/寄生 |
| 接取 vs 接取 | 双方各 +1 |
| 接取 vs 防御 | 接取成功且无伤害 |
| 防御 vs 防御 | 双方无事 |

- **强制改防御**（`forcedChanges` 记录）：被束缚却选择非复读动作、接取水/土、资源不足、重复铸造已有武器。
- **荆棘之墙**：对伤害免疫并把该次伤害**反弹 1 点**给攻击者（穿甲弹可击碎墙：伤害提升为 2 且不反弹）。

## 5. 元素路线与效果（route 名 / 消耗 / 效果）

### 金（Jin）
| route | 消耗 | 效果 |
|---|---|---|
| `attack` 金之斩 | 1 金 | 1 点伤害 |
| `craftGatling` 铸造加特林 | 1 金 | 获得加特林（已有则不可再铸） |
| `gatlingFire` 加特林射击 | N 金 | 2N 发子弹，每发 1 伤，独立计算防御减伤 |
| `craftDual` 铸造双枪 | 1 金 | 获得双枪（已有则不可再铸） |
| `dualFire` 双枪射击 | 1 金 | 2 点伤害 |
| `craftAP` 铸造穿甲弹 | 1 金 | 穿甲弹 +1 |
| `apFire` 穿甲射击 | 1 枚穿甲弹 | 1 点伤害，**无视防御**；若目标有荆棘之墙 → 击碎墙，伤害提升为 2 |

### 木（Mu）
| route | 消耗 | 效果 |
|---|---|---|
| `attack` 木之刺 | 1 木 | 1 点伤害 |
| `bind` 藤蔓束缚 | 1 木 | 指定目标被束缚 2 回合，只能防御、复读上一动作或以金之斩挣脱（穿透防御）。**束缚不可叠加**：已束缚的目标免疫新束缚（施放无效且不消耗木） |
| `seed` 种子寄生 | 2 木 | 1 点伤害 + 本回合末随机偷取对方 1 元素（防御可驱散） |
| `thorn` 荆棘之墙 | 2 木 | 本回合免疫伤害并反弹 1 点 |

**束缚反制规则**：① **受击解绑（严格版）**——本回合因他人伤害实际掉血（含灼烧 tick）则束缚立即断裂；被防御减为 0 的伤害不触发。② **金之斩双职**——被束缚者可选用金之斩（1 金），解除自身束缚并正常造成 1 点伤害；无金时仍被迫防御。火系不参与解控（保持输出定位）。

### 火（Huo）
| route | 消耗 | 效果 |
|---|---|---|
| `fireball` 火球术 | 1 火 | 1 点伤害，可指定目标 |
| `fireRain` 火球雨 | 全部火 | 每 1 火指定 1 个**不同**目标各 1 伤（单一目标只能被指定 1 次；1v1 只打 1 伤，多余火溢出浪费） |
| `blaze` 烈焰爆发 | 2 火 | 3 点伤害 + 自身反噬 1 点 |
| `burn` 灼烧烙印 | 2 火 | 1 点伤害 + 灼烧 2 回合（每回合末 1 伤，无视防御；防御可驱散）。**被防御时伤害归 0，但灼烧状态仍先附加、再被防御驱散** |

## 6. 状态与回合末结算（顺序固定）
每回合结束时按以下顺序统一处理：
1. **防御驱散**：防御者清除灼烧/寄生状态。
2. **灼烧扣血**：本回合开始时 `burnTurns > 0` 且未防御 → -1 HP，灼烧持续回合数 -1。
3. **种子偷取**：本回合开始时 `seedTurns > 0` 且未防御 → -1 HP 对应元素 1 枚随机转移给寄生者，持续回合 -1。
4. **束缚递减**：本回合开始时 `bindTurns > 0` → 递减（`bindTurns = 2` 实际束缚 2 回合）。

> 状态是否生效以"本回合开始时"的快照为准，避免同回合重复触发。

## 7. 生命值与胜负
- 双方初始 **3** HP，钳制在 `[0, 3]`。
- 任一 HP ≤ 0 时游戏结束：一方归零则对方胜；双方同时归零则**平局**。
- **多人就绪（引擎层）**：`new GameEngine(N)` 支持 2–9 人；动作可携带 `targets: [下标]`；双枪在多人局必须指向**不同**目标（1v1 可集火）；火球雨按目标分流；胜负为**最后存活者**。UI 多人界面待下一版本。

## 8. 回合流程（状态机）
- **READY**：显示双方 HP/元素/武器/状态，玩家选择接取、使用或防御。
- **LOCK**：玩家出招后 AI 延时 0.5s 出招，进入结算。
- **RESULT**：应用变化 → 播放动画 → 展示文字战报与胜负。
- **下一回合**：点击按钮回到 READY；分出胜负则弹窗提示并可选"重新开局"。

## 9. AI 决策（ai.js）
- 五种行为模式，开局随机抽取、整局不变：**金匠 / 木控 / 火爆 / 均衡 / 防守**（`BEHAVIORS`、`BEHAVIOR_LABEL`）。
- `chooseAIAction(aiPlayer, opponent, allPlayers, behavior)` 加权随机挑选合法动作：
  - 金匠优先铸造并扫射加特林/双枪/穿甲；木控优先束缚/寄生/荆棘；火爆优先火系输出；防守高频防御；均衡混合。
  - 各行为按偏好给接取/防御/铸造/攻击/状态路线加权，`isFeasible` 过滤不可行动作。
  - **斩杀优先**：对手 HP ≤ 1 时大幅提高补刀路线权重。
  - **束缚中**：可消耗 1 金以金之斩挣脱（约 40% 概率），否则防御或复读上一动作（均不可行则防御）。
  - 永不含水/土接取、绝不选无法支付的路线。

## 10. 表现层（index.html / style.css / main.js）
- **HUD**：♥/♡ 心形血量（`3/3`，剩 1 血红闪）、五行元素块（各元素独立配色，水/土虚线置灰）、武器芯片（加特林/双枪/穿甲弹）、状态芯片（束缚/灼烧/寄生，闪烁）。
- **操作**：接取弹子菜单（水/土禁用）；使用弹路线菜单（不可行路线自动禁用；加特林射击弹出消耗量选择）；防御一键出招。被束缚时：使用面板仅开放**金之斩**与**上回合路线**（复读加特林自动按原消耗量提交），接取面板仅在上回合为接取时开放对应元素，无可用项时提示改选防御。
- **动画**：各招式独立特效——铸造=金色火花上浮+"铸造"字样；金之斩=金色刀光弧线；加特林=多枚连发弹道；双枪=两发弹道；穿甲=银白长弹疾射；火球=元素火球；火球雨=连串弹道；烈焰爆发=目标处爆炸环；灼烧=火球+目标灼烧火焰；藤蔓束缚=绿色藤环缠住目标；种子寄生=绿种飞射+目标生长；荆棘之墙=绿色荆棘环护体。接取=元素 +1 浮动；防御=护盾；受击=震动变色；背景光晕漂移、VS 徽章旋转、角色 aura 呼吸。
- **战报**：按行分类着色——伤害（红）、防御（蓝）、接取/铸造（黄绿）、束缚（绿）、种子（青）、被迫/击碎/打断（红）。
- **弹窗**：胜负 + 奖杯，可重新开局（AI 行为模式随新局重新抽取）。

## 11. 架构（为联机预留）
- `engine.js`：`GameEngine` 类，纯数据进出（输入动作对象，输出 `report`），**不依赖 DOM**；构造器支持 `playerCount`（默认 2），结算循环、荆棘墙、反弹、胜负均已按 N 人泛化。
- `ai.js`：AI 决策，纯逻辑，不依赖 DOM（当前仍为 1v1 视角，多人 AI 待扩展）。
- `main.js`：DOM 表现层，读取 `engine` 状态渲染。
- `report` 字段：`p1/p2_hp_change`（前两名兼容字段）、`hpChanges`（全员数组）、`actions`（归一化后的实际动作，键 p1..pN）、`forcedChanges`（强制改防御记录：player/from/to/reason）、`winner`、`state`、`players`（深拷贝快照）、`log_message`。
